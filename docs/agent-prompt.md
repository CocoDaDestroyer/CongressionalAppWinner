You are taking over CartWise, a React + Vite + TypeScript + Tailwind v4 grocery price-comparison app in this repo. It is an entry for the Congressional App Challenge. Judges score (1) the quality of the idea, (2) the implementation, including UX and design, and (3) coding skill, and they mostly see the app through a 1-3 minute demo video. Your job is to make this app look as polished and professional as possible, and to make every feature work cleanly on screen. It does NOT need to scale, handle real traffic, or be secure. Do not spend any time on backend, auth, RLS, rate limiting, or hardening.

READ FIRST, in this order: CLAUDE.md (all of it, especially "Purpose", "Working without a backend", "Trip planning" and "Price provenance"), docs/polish-plan.md, then src/lib/*.ts, src/routes/*.tsx, src/data/seed.ts and the tests. Run `npm ci`, `npx vitest run`, `npm run typecheck` and `npm run lint` to confirm the green baseline (70 tests pass) before changing anything.

HARD RULES (do not break these):
- Keep the architecture. Screens read data only through `useCatalog()` / `useReceipts()` from `src/lib/useCatalog.ts`. New mutations go through `catalogStore` in `src/lib/store.ts`. Never build a repository inside a component. Every `useMemo` that derives from the repo must list the repo as a dependency.
- Prices are always compared per unit with `normalize()` / `cheapestFirst()` from `src/lib/units.ts`. Price observations carry a source and a timestamp. Freshest wins, and ties go to the more trusted source (scrape > loyalty_sync > receipt > user_report). If you add an ingestion path, follow those rules and add tests.
- Fake the data source, never the logic. What a screen shows must come from the real compare/trip/store code. Seeding more data is fine; hard-coding results in JSX is not.
- Keep seed data's deliberate edge cases intact (the big package that wins per unit, the store brand that is cheapest and worst reviewed, member pricing, the stale user report next to a fresh scrape, the cheap but distant store). Add to the seed; don't distort it.
- No paid services and no hosting setup. Everything runs locally from `npm run dev`. Supabase stays unused.
- Tests must stay green. A redesign will break selectors such as `getByRole('table')`, slider roles, the "Save receipt"/"Add line"/"Delete" button names, and the "Item 1"/"Price 1"/"Purchased" labels. When you change markup, update the selectors deliberately and keep every behavioral assertion. Never delete a test to get green. Add tests for each new feature's logic (for example, spend aggregation and membership effects). Component tests need `// @vitest-environment jsdom` at the top.
- After each phase, run `npx vitest run`, `npm run typecheck`, `npm run lint` and `npm run build`. Then commit with a clear message and push to the current branch. Do not open a PR unless asked.

DESIGN DIRECTION (decide it, write it down, then follow it everywhere):
1. Create `docs/design.md` first. Brand: "CartWise: smart grocery savings." Fresh, trustworthy and slightly playful. A green/teal primary, one warm accent (amber/orange) used ONLY for savings and "best value" callouts, and neutral slate surfaces. A characterful heading font (Plus Jakarta Sans or Outfit from Google Fonts) and a clean body font. Generous radius (12-16px) and soft but sparing shadows. Define a type scale, spacing rhythm and motion rules (150-250ms, ease-out, honor prefers-reduced-motion). Borrow hierarchy from Apple Wallet/Revolut (cards), Instacart (product rows) and Copilot Money (spend charts).
2. Avoid the generic AI-app look: no purple-to-blue gradients, no glassmorphism everywhere, no emoji as icons, no shadow on every element, no walls of identical cards. Use lucide-react icons. Keep color restrained so the savings numbers stand out.
3. Put tokens in `src/index.css` using Tailwind v4 `@theme`, with CSS variables for light and dark mode (follow the OS setting, plus a toggle in settings). Do not hard-code hex colors in components.

PHASE 1: Foundation
- Install shadcn/ui using its Vite + Tailwind v4 instructions (uses `tw-animate-css`, not `tailwindcss-animate`), plus `lucide-react` and `sonner`. Add `recharts` for Spending, and optionally `motion` for transitions. Only add primitives you actually use.
- Create `src/components/`: AppShell, PageHeader, StatTile, PriceTag (sticker price small, per-unit price prominent), SourceBadge (scrape/loyalty/receipt/community, plus stale and member variants), QualityStars, EmptyState, Skeleton, and a quantity Stepper.
- App shell: mobile-first, with a bottom tab bar (Scan, List, Receipts, Spending, Community) and a "More" sheet (Contribute, Memberships, Settings). On wide screens, a left sidebar with the logo. The content column is centered with a sensible max width so desktop screenshots look intentional.
- Replace the Vite favicon with a simple SVG logo (a cart with a check or a price tag). Set the title and meta description, and use the logo in the shell.

PHASE 2: Redesign the three working screens
- Scan: a hero "scanner" card with a camera-viewfinder frame and an animated scan line. Inside it, a searchable product picker (shadcn Command/Combobox) and barcode entry. Below that, two prominent recommendation cards: "Best value" (accent color, with a short "why" line) and "Cheapest per unit". Then the ranked options as clean rows: product and brand, store with a distance chip, sticker price, a large per-unit price, quality stars with review count, and source/freshness badges. Present the quality-versus-price weight as a labeled slider ("Price ← → Quality"). For an unknown barcode, show a friendly empty state with a button that goes to Contribute, prefilled with the GTIN.
- List: a list builder with an icon per item and quantity steppers, and a "max stores" control. The summary card shows the headline total including fuel, with the savings versus "one store" and versus "cheapest everywhere, ignoring the drive" as count-up numbers. Then one card per store stop with its items. Add a stylized SVG route diagram (home → stops → home, with miles); no Maps API.
- Receipts: a form styled like a receipt (store picker, date, line items with steppers, a running total). On save, show a sonner toast ("Receipt saved: updated N prices") that links to Scan. A history list with store logo/initial, date, total and delete (with confirmation).
- Remove every "Styling is deliberately plain / design comes later" comment.

PHASE 3: Build the stub screens into real features (local data, real logic, tests)
- Spending: derive monthly and annual totals from saved receipts through a pure function in `src/lib/` (unit tested). Show stat tiles (this month, this year, average per trip), a recharts bar chart by month, and breakdowns by store and by category. Add 4-6 months of realistic historical receipts to the seed so the chart looks full (keep the existing seed properties and tests intact).
- Memberships: loyalty cards for the seeded retailers, styled like wallet cards. "Link account" runs a simulated connect flow (a dialog, about a 1s loading state, then success), and the linked state persists in `catalogStore`. Linked memberships must feed the existing member-price logic, so linking visibly changes the Scan and List results. Move the List screen's "has Ralphs card" toggle here (List reads it from the store).
- Contribute: an "Add a product or price" form (product or new package, store, price, date). It writes a `user_report` observation through `catalogStore`. In Scan the entry shows a "Community" badge, and a fresher scraped price still beats it per the provenance rules. Test this.
- Community: locality-scoped threads (e.g. "Westwood, LA"). Seed 8-12 believable posts with authors, avatars (initials), relative times, tags (Deals, Tips, Store reviews), replies and upvotes. Creating a post, replying and upvoting persist locally through the same store pattern. Product and store mentions render as chips that link to Scan.

PHASE 4: Delight and consistency
- A landing/onboarding route ("Save on every grocery run"): three value props with icons and a "Start saving" button. Show it on first visit and skip it afterwards (stored in localStorage, with try/catch).
- Subtle page transitions and count-up animations on the savings numbers only. Show skeletons briefly on first load.
- Settings: theme toggle, home location label, and "Reset demo data" (restores the seed and clears saved receipts, posts and links).
- Design every loading, empty and error state. Search for and remove leftover "stub", "--" placeholders, `gray-600` one-offs that skip the tokens, and inconsistent spacing.
- Accessibility basics: every input labeled, visible focus rings, AA contrast in both themes, and 44px tap targets on mobile.
